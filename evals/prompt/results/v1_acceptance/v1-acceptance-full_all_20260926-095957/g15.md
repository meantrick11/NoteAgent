## 5. 输入

```text
Turn the English incident note below into a Chinese note, and keep the root cause, the symptom and the workaround clearly separated.

Symptoms: users reported that the search page returned 503 for about eleven minutes starting at 02:14 UTC. Root cause: a nightly job rebuilt the search index in place, and the rebuild deleted the serving alias before recreating it, so queries hit a missing index. The job had run safely for months because the rebuild used to finish before traffic peaked; last night it took 40 percent longer after the index grew. Workaround applied during the incident: we pointed the alias back at the previous index, which restored traffic in about ninety seconds. Follow-up: the rebuild now writes to a temporary index and switches the alias at the end, so there is no window without a serving index. The client should also honour Retry-After on 503 and back off instead of retrying immediately.
```

```markdown
## 现象

用户反馈搜索页从 02:14 UTC 起约十一分钟内返回 503。

## 根因

一个夜间任务就地重建搜索索引，重建时先删除 serving `alias` 再重新创建，因此查询会命中缺失的索引。

该任务此前已安全运行数月，原因是重建过去总能在流量高峰前完成；昨晚索引增长后，重建耗时增加了 40%。

## 事件期间的临时处置

把 `alias` 重新指回上一个索引，约 90 秒内恢复了流量。

## 后续修复

重建改为写入一个临时索引，最后再切换 `alias`，因此不再出现没有可用索引的窗口。

另外，客户端在收到 503 时应遵守 `Retry-After`，改为退避重试，而不是立即重试。
```
