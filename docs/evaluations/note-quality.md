# 笔记正文质量准则（v0.2）

本文是离线评价 `propose_note` Markdown 正文的质量契约，用于比较记笔记提示词版本。它不评价工具、RAG、人审 UX，也不在运行时拦截或自动重写草稿。

`rubric_version`：**v0.2**。v0.2 改变了质量定义和合格判定，**不得与 v0.1 直接比较总分或排名**。

数据集见 [evals/prompt/](../../evals/prompt/README.md)。旧 case 保持 v0.1 的 `total` / `parents` 行为；`learning_note` case 使用确定性检查加可选语义 Judge，并以三道硬门和配置维度阈值决定 `qualified`。

## 1. 任务边界

评价始终相对于“来源材料 + 用户要求”，不能脱离当前任务追求抽象的丰富或美观。

- 默认“整理成笔记”是学习型笔记：保留来源范围和关键语义，允许有依据的分组、去重、对比与因果重组。
- 显式“只要提纲”只要求提纲范围内的信息。
- 显式“只要某节”只评价该节，不因省略范围外内容扣分。
- 显式“完全忠实翻译”应完整翻译并尊重原结构，不强求学习型重组。
- 普通翻译并整理为笔记时，可翻译标题并按语义组织，但不能改变事实、关系、条件、模态或例外。

不得补充来源未给出的外部背景。即使外部知识本身正确，只要来源不能支持，它也不是本任务的“知识加工增益”，并可能导致忠实硬门失败。

## 2. 合格判定

先判断三道硬门：

1. **任务匹配（task alignment）**：输出执行了用户要求的任务类型、范围和语言。
2. **忠实（faithful）**：草稿中的每个事实性命题都能被来源支持，且条件、模态和例外没有被加强、削弱或反转。
3. **完整（complete）**：当前任务范围内的关键语义单元及其必要关系得到覆盖。

任一硬门失败，都不得输出“合格”结论，也不得用结构、流畅、形态、可检索或知识加工增益的高分抵消。行为门（是否提案、工具顺序、action 是否正确）仍单独记录；行为失败时不对空草稿打正文质量分。

本准则共表达七个正文质量方面：**faithful、complete** 只作为硬门，不再另打 0–4 分；**structure、fluent、form、retrievable、processing** 是五个 0–4 维度。`task_alignment` 是七个正文质量方面之外的额外任务门。五维分用于解释差异，不替代硬门。

## 3. 七个质量方面

### 3.1 忠实

核心问题：**草稿中的命题能否由来源支持？**

检查事实、数字、代码、命令、术语、因果、比较、条件、模态与例外。省略内容归完整；写入矛盾、无来源事实，或把“通常 / 可能 / may / typically”改成“一定”，归忠实。

有依据的同义改写、翻译、合并和语义重排不算失真。不能因为某个观点听起来合理或符合常识，就视为得到来源支持。

### 3.2 完整

核心问题：**任务范围内的关键语义单元是否被覆盖？**

语义单元包括主要事实、目的、限制、例子类别、步骤、结论，以及理解这些内容所必需的因果、对比、递进关系。完整不要求逐句复刻；多个句子可合并，一个复杂关系也可拆开，只要信息和关系仍可从笔记中恢复。

完整的边界由任务决定：提纲、节选和完全忠实翻译分别按其明确范围评价。

忠实与完整的结果均为通过/失败，不使用 0–4 分，以免让结构或文笔分数抵消事实与覆盖缺陷。

### 3.3 结构

核心问题：**来源范围是否被尊重，并形成有依据的语义组织？**

必须保留用户指定的顶层范围、章节边界和不可丢失的层级关系。学习型笔记允许新增有来源依据的语义子标题，也允许按主题、因果、对比或学习顺序重组段落；不得因没有逐字复刻原标题树而自动扣分。

结构重组不能跨越用户排除的范围，不能把不同条件下的结论错误合并，也不能用自拟标题暗示来源没有表达的结论。显式要求完全忠实翻译时，原结构本身就是任务约束。

### 3.4 流畅

核心问题：笔记是否通顺、连贯，术语和译名是否前后一致？翻译任务还要避免生硬逐词映射，但不得以润色为由改变语义。

### 3.5 形态

核心问题：Markdown 是否服务于内容？标题、段落、列表、引用和代码围栏应与信息类型相匹配，避免通篇口号式短列表或错误代码格式。形态正确不能弥补语义缺失。

### 3.6 可检索

核心问题：合法路径、文件名和正文中的稳定主题词是否便于以后找到这篇笔记？可检索只评价检索线索，不重复计算忠实、完整或结构。

### 3.7 知识加工增益

核心问题：在不引入外部事实的前提下，笔记是否降低了读者重新解析原文的成本？

| 分值 | 定义 |
|---|---|
| 0 | 逐句照译或近乎逐句搬运，没有实质组织。 |
| 1 | 只有措辞、语言或 Markdown 格式变化，语义顺序基本照搬。 |
| 2 | 完成基本语义分组、去重或局部归纳，但关键关系仍多靠读者自行还原。 |
| 3 | 显式呈现主要因果、对比或递进，并围绕学习主题组织内容。 |
| 4 | 形成可直接学习和复习的结构；无需重新解析原文即可掌握关键语义单元及其关系。 |

技术事实、命令、代码、数字可贴近原文。加工增益主要来自对来源已有的说理、动机、比较和路径进行实质组织，而不是制造新知识。复习问题只能用于验证笔记是否承载原文信息，不能诱导补充来源外答案。

## 4. 语义评价禁区

以下量只能用于诊断格式或数据异常，**不得作为语义质量、完整、结构或加工增益的替代指标**：

- 来源与草稿的字符比、压缩比或篇幅比例；
- 句子边界重合度、逐句对齐率；
- 标题数量、标题字面重合数量；
- BLEU、ROUGE 或 embedding 相似度。

一篇短笔记可能语义完整，一篇长笔记也可能遗漏或幻觉；标题增减可能是合理重组，也可能是假结构。语义结论必须落到具体命题、语义单元、关系、模态或例外的证据上。

确定性的锚点、字面量、代码围栏和 Markdown 检查只作为可审计诊断，不能以容易误报的字面规则覆盖语义 Judge 对忠实、完整、结构或加工增益的结论。工具顺序、action 和输出路径是否合法仍由行为门处理。

## 5. 证据与报告契约

离线报告必须记录数据集路径、case id、rubric 版本、Prompt hash、生成模型和时间。每个硬门与维度均保留：

- 判定或 0–4 分值；
- 来源证据（`request.task` 原样逐字连续片段）；
- 草稿证据（`draft.content` 原样逐字连续片段；`retrievable` 还可引用 `draft.file_name`）；
- 缺失、冲突或无支持命题；
- 未完成项及原因。

若 case 配置了复习问题，Judge 还必须逐题记录问题原文、`answerable`、答案、草稿证据或不可回答原因。只有全部问题都能仅依据草稿正文回答时，复习问题验收才通过；不能查看来源替草稿补答案。

语义 Judge 缺失或解析失败时标记“未完成”，不得将未评项摊权成虚高总分。若生成模型与 Judge 模型相同，必须标记 `judge_independent=false`，不能声称是独立校准。

运行学习型校准：

```bash
python scripts/eval_notes.py --judge --cases evals/prompt/learning_notes.jsonl --ids l01
```

启用前必须配置 `DEEPSEEK_API_KEY` 和非空 `JUDGE_MODEL`。`JUDGE_MODEL` 可与 `CHAT_MODEL` 相同，但这只表示第二次评分调用，不构成独立模型校准。不传 `--judge` 时不会调用评分模型，报告中的 `qualified`、硬门和语义维度保持未完成。Judge 返回非严格 JSON、缺字段、空证据、0–4 越界分数，或复习问题数量、顺序、草稿证据不符合契约时，本次语义评测失败并在配置中留痕。普通评测的 `config.json` 记录实际 cases JSONL 的 SHA256；启用 Judge 时结果目录同时归档固定文件名 `judge_prompt.txt`。

## 6. 校准集契约

第一期学习型校准集为 [`learning_notes.jsonl`](../../evals/prompt/learning_notes.jsonl)，固定材料是 Python 官方教程第 1 章 “Whetting Your Appetite”。四个候选位于 [`fixtures/learning_notes/`](../../evals/prompt/fixtures/learning_notes/)：

1. `good.md`：忠实、完整并有语义重组；
2. `literal.md`：忠实且完整，但接近逐段译文；
3. `omitted.md`：可读且漂亮，但遗漏关键语义；
4. `hallucinated.md`：可读，却加入来源未支持的事实。

固定人工排序契约为：

```text
good > literal > omitted
hallucinated 必须被忠实硬门淘汰
```

`good.md` 应通过全部硬门、能回答全部复习问题，且结构、流畅、知识加工增益均不低于 3/4；`literal.md` 应通过忠实与完整，但仍因加工或结构阈值不足而不合格，不以复习题结果替代该区分；`omitted.md` 应在完整硬门失败且至少一个相关复习问题不可回答；`hallucinated.md` 应在忠实硬门失败，不要求幻觉答案被判为可回答。单个教程样本通过只代表第一阶段校准，不代表已泛化到所有教程。
