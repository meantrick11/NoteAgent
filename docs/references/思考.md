# 这个文件是用来记录开发过程中的所思所想的

## 项目目标

兰台项目初始背景是解决在观看视频，浏览网页，面试等等需要记录的场景下，生成对应的笔记/记录文件，方便用户进行后续无论是知识复盘，日报/周报，面试总结等等作用，通过AI辅助生成纪要/笔记，解决用户需要手动记录的问题

## 项目的设计

### 前端

前端当前有两个页面，一个是：用户可以通过此页面进行对话聊天，后端AI进行对话整理为合适的笔记文件，交给用户审批，如果通过那么再写入磁盘，进行保留，另外一个是：documents的文件管理，用户可以在线编辑和查看状态

后续可以考虑多个功能，多个页面等等，比如Agent权限，OCR等等功能上的扩展

### 后端

#### Agent

##### LLM

通过langchain中的init_model获取用户的deepseekAPI进行初始化模型

##### 工具

有list\read\search\propose四个原生工具，其中list是列出notes/文件夹下的完整的笔记清单，read是获取对应文件中的内容，search是向量检索RAG数据库中的相关笔记片段，**propose是Agent在判断需要生成笔记之后发起请求，生成对应的草稿，让用户前端同意，然后最后再写入文件，落到磁盘（唯一的能够写入磁盘的操作）**

通过langchain的@tool修饰器进行将工具绑定到模型上

##### RAG

RAG当前决策是在用户同意新建笔记之后，系统就先写入对应文件，然后调用langchain的文本分割器进行分割，然后调用本地的all-Min模型进行向量化，最后直接入库到Chroma当中，整个过程只是能够跑通，但是质量可能不高。（暂时没有让用户手动进行入库等操作，小demo直接在文件更新之后就直接进行检索入库）

**入库之前如果是对旧文件进行修改，那么先删除向量数据库中的旧数据，然后再对整个文件进行分片等操作，因为确保时效性，完整性**

后续可以考虑用户传入不同的文本内容也要求入库等等，以及分块模型的选用，向量数据库的使用，如何提高检索质量等等

#### 数据库

##### pg数据库

pg数据库当前有两张表，一张就是conversation及其映射的message表

conversation记录的是具体聊天历史索引，区分不同的聊天

每个message当中有turn字段确定不同轮次，方便后续短期记忆进行压缩，不同类型的回复(user/assistant/tool)，tool对应有tool_name,参数,工具截断，工具返回结果的路径映射(方便前端建立索引)等等

#### 向量数据库

向量数据库中存有对应片段的维度信息，方便RAG进行检索，具体信息可以参考[retrieval具体实现](../architecture/retrieval.md)
