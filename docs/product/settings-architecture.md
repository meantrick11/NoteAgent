# Settings 分类与未来个人中心边界

**状态：** 2026-09-28 已实施。齿轮入口与两个可用分类已落地，执行记录见
[结果文档](../plans/2026-09-28-settings-navigation-and-sections-results.md)；其余五个分类仍只预留 ID。
用户已确认暂用设置图标，个人中心在多用户阶段引入。

**关联：** [前端总体设计](frontend-architecture.md)、[现行前端](../architecture/frontend.md)、[执行计划](../plans/2026-09-28-settings-navigation-and-sections.md)。

## 1. 目标与现状

Settings 是应用配置的统一入口，不能在产品结构上被限定为模型切换。当前可用配置仍只有现有聊天模型、向量模型和索引维护；扩展架构不意味着提前实现未来业务。

代码现状（2026-09-28 实施后）：`frontend/src/shared/navigation.ts` 导出 `PRIMARY_NAV_ITEMS`（四个工作入口）、
`SETTINGS_ENTRY`（齿轮）与 `HOME_SHORTCUTS`（Home 四张快捷卡）；`layouts/AppShell.vue` 的输出四个文字项
加一个齿轮。SettingsPage 按 `?section=` 选类，分类定义在 `features/settings/sections.ts`，
两个可用分类同时挂载、只切换显隐。内容仍是原来的 `ChatProfiles` 与 `EmbeddingSettings`，
与 Assistant 快捷弹层共享 `features/models/store.ts`。

## 2. 入口与布局

- 顶部主导航为 Home、Assistant、Records、Library，顺序不变；右上角独立齿轮链接进入 `/settings`。
- 齿轮使用原生 SVG／现有图标方式，带可访问名称“设置”、悬停说明、键盘焦点与选中态，不新增图标库。
- Home 仍保留 Assistant、Records、Library、Settings 四个快捷入口。移走顶部文字项不影响页面、路由或 Home 功能。
- 设置页面采用左侧分类、右侧内容。宽屏两栏；窄屏分类位于内容上方，允许换行，控件仍可操作。
- 标题使用“设置”；首轮分类为“模型与连接”“检索与索引”。默认进入前者。
- `/settings?section=models` 与 `/settings?section=retrieval` 表示分类；裸 `/settings` 默认 models，未知或未开放值 replace 为 models，保留其他 query 参数。
- 分类使用链接而非模拟 tab，位于名为“设置分类”的导航中；选中项有 aria-current。浏览器前后退和刷新恢复分类。
- 分类切换保留当前模型表单的未提交文本，不能因隐藏另一分类而重新创建表单；没有新增自动保存。完整离开设置页沿用既有行为，本轮不新增跨会话表单缓存或密钥持久化。
- 页面用面向用户的说明，例如“管理模型连接、检索与应用偏好”；不向用户展示 store、组件复用等实现说明。

## 3. 分类规划及开放条件

下列后续功能为候选范围，不是当前实现承诺。预留分类的 ID 与归属有文档定义即可；没有能力支持时不显示空菜单、假数值、不可用的保存按钮。

| ID | 分类 | 当前交付 | 后续预留功能 | 开放前提 |
|---|---|---|---|---|
| models | 模型与连接 | 复用 ChatProfiles：配置增改删、连接测试、保存、启用、凭据处理 | 更多服务连接及不同用途的模型配置 | 实际服务合同、凭据归属与权限明确 |
| retrieval | 检索与索引 | 复用 EmbeddingSettings 及现有摘要：向量候选、索引状态、切换、修复、进度与错误 | 可配置的检索偏好和索引策略 | 后端支持、参数校验及评测验证；不提前暴露全部技术参数 |
| general | 通用与外观 | 只预留 ID，不展示菜单 | 主题、界面语言、字号、启动偏好 | 有真实偏好读写与可观察效果 |
| editor | 编辑与阅读 | 只预留 ID，不展示菜单 | 编辑／预览偏好、阅读显示 | 编辑器支持且定义保存范围；不暗改笔记内容 |
| data | 数据与存储 | 只预留 ID，不展示菜单 | 导入导出、备份恢复、同步偏好 | 数据范围、失败恢复与服务端权限明确 |
| recording | 记录与采集 | 只预留 ID，不展示菜单 | 默认输入设备、采集权限、记录保存偏好 | Records 提供对应真实能力 |
| organization | 整理偏好 | 只预留 ID，不展示菜单 | 默认语言、详细程度、默认整理方案 | V2 整理方案及版本语义已实现；完整方案管理页面另行设计 |

选择简单的静态分类定义即可。首轮渲染两项；其余标记 reserved，经过过滤不能点击或路由进入。不建设设置插件系统、远程菜单、万能表单、分类管理后台。

## 4. 设置、业务操作、个人中心与管理后台

- Settings 保存长期默认偏好；本次工作的一次性选择留在 Assistant／Records／Library。例如默认采集设备可以放设置，本次录制的设备选择留在 Records。
- 个人中心承载账号身份、账号安全和个人服务信息。当前没有用户体系，不创建头像资料、登录、会员、退出登录等页面或伪用户数据。
- 以后有用户体系时，可以将右上角入口扩展成头像菜单，含个人中心、设置、退出登录；保持 `/settings` 的稳定地址。当前不编写未使用的 UserMenu 占位组件。
- 多用户阶段需区分用户级偏好、用户自己的连接，以及管理员控制的平台模型、公共索引和服务配置。当前本地单用户配置不能直接解释成未来用户个人配置。
- 用户管理、平台凭据、公共索引维护归平台管理权限。前端隐藏按钮不构成权限控制；必须配套服务端身份、授权和数据隔离后才能开放。
- 本轮不添加 user_id、认证、RBAC、租户表或云部署设置，不迁移现有配置数据。

## 5. 实现边界与验收

沿用 Vue Router、现有 models store 与模型组件，不变更 API、revision、凭据保留语义、busy、streaming 或轮询生命周期。Settings 分类不启动另一份模型状态服务。Assistant 的两个快捷弹层继续完整可用。

增加分类导航后，原 Settings 顶层的向量摘要移入“检索与索引”，不得删除当前模型、状态、片段／笔记计数、维护与任务阶段展示。第一类不再同时展示向量配置属于分类展示调整，功能仍全部可达。

验收重点：主导航四项＋齿轮；Home 四快捷入口；两类设置可直达、刷新和前后退；分类切换不丢表单；现有全部配置操作保留；无预留功能假界面。实现完成后才更新现行架构的已实现导航描述。
