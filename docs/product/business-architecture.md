# NoteAgent 产品与业务架构

> 2026-09-22：根据产品讨论形成的上层业务基线。本文包含目标能力，不代表这些能力已经实现；当前实现见 [现行架构](../architecture/architecture.md)，交付范围与验收见 [版本路线](../roadmap/versions.md)。术语统一见 [CONTEXT.md](../../CONTEXT.md)。

## 1. 产品目标与边界

NoteAgent 帮助用户把接触过的内容，按自己的要求记录、整理为有来源、可核对、可检索、可再次加工的个人材料。

记录对象可以来自对话、网页、文件、视频或会议。用户决定记录范围、整理要求和保存结果；系统减少复制、截图、归档以及日后寻找内容的工作。学习是重要场景，操作记录、会议记录也在业务范围内。

当前起点是“聊天 → 草稿 → 人审 → Markdown → RAG 检索”。后续每增加一种来源，都应完成该场景的记录与复用闭环。支持更多来源并不意味着一次开发覆盖所有网站、文件格式或采集环境。

本轮确定的方向：

- 来源与整理结果保持关联；截图、时间位置和文字的对应关系属于材料价值的一部分。
- 笔记是可复用材料的一种形态，Markdown 是当前文字内容的主要载体。
- 用户定制能力先体现为可保存、可再次使用的整理方案；更深的工具与流程定制需要独立验证需求。
- 正式材料的创建、修改和删除由用户操作或用户确认触发。
- 首先服务个人使用；团队协作、账号平台化、通用工作流市场不属于当前版本承诺。

## 2. 用户场景与业务结果

| 场景 | 用户指定的范围与要求 | 应交付的结果 | 复用方式 | 阶段 |
|------|--------------------|--------------|----------|------|
| 聊天记录 | 选定内容或本次明确要求 | 可预览、修改和确认的文字笔记 | 在后续对话中检索并回答 | V1 验收起点 |
| 网页记录 | 指定 URL；以后扩展页面选区 | 按整理方案生成、带来源依据的材料 | 搜索结论、回看获取时的依据 | V2 |
| 文件记录 | 指定文件及支持的页码或章节范围 | 保留结构与定位的整理材料 | 找到材料并定位到原页或章节 | V3.1 |
| 图片记录 | 指定图片或截图 | 保留图片、文字及对应区域的材料 | 检索文字并核对原图 | V3.2 |
| 会议记录 | 先支持导入录音，指定议题整理要求 | 议题、讨论、决定与待办，附时间依据 | 查找决定、回听相关发言 | V3.3 离线闭环 |
| 视频与区域记录 | 指定录制片段，或开始一次限定区域采集 | 图片＋定位＋文字相互关联的材料 | 找到步骤并回看画面及音频 | V3.4，先离线再实时 |
| 多材料再加工 | 选择已保存材料和输出要求 | 对比、总结、复习资料或文章草稿 | 保存为新材料并继续追溯依据 | V3.5 |

阶段编号是交付分组；会议录音与视频场景的启动顺序可以根据实际使用优先级调整。完整版本与单个场景试点的完成范围必须分别声明。

聊天始终可以用于询问和修改要求，但未来还可以通过 URL 输入、文件导入或采集操作发起任务。浏览器扩展、桌面浮窗和自动识别当前页面是入口方案，需要独立立项；“支持 URL”不等于已经能读取用户当前浏览器页面。

## 3. 共同业务链路

| 步骤 | 用户与系统的责任 | 产物及完成条件 |
|------|----------------|----------------|
| 1. 指定任务 | 用户选择来源、范围和整理要求；范围不明确时先澄清 | 明确本次记录边界；普通聊天不自动变成记录任务 |
| 2. 获取来源 | 系统在指定范围内获取内容，保存定位和必要的核对依据 | 能区分成功、部分获取和失败；不能把未获取部分当作已读 |
| 3. 整理草稿 | 按方案组织内容，保持事实、推论与补充的区别 | 草稿关联来源；缺失或不确定处可见 |
| 4. 核对修改 | 用户查看正文、图片、来源和改动，可编辑、退回或拒绝 | 用户确认的是具体内容及变更范围 |
| 5. 保存材料 | 确定性程序保存确认结果，随后更新检索索引 | 保存状态与索引状态分别可见，重试不重复写入 |
| 6. 检索复用 | 用户在新问题或任务中查找、引用、回看或再次整理 | 命中有效版本；依据不足时说明不足；新成果先作为草稿 |

获取和整理允许分时进行：会议期间持续采集，会后整理；同一网页只获取一次，也可以按不同方案生成多种结果。持续采集的中间保存不等于批准其进入正式材料库。

## 4. 核心对象与关系

| 对象 | 业务责任 | 关系与边界 |
|------|----------|------------|
| 记录任务 | 记录目标、范围、采用的方案和处理结果 | 可关联多个来源和多个草稿；未来独立于聊天会话存在 |
| 来源及片段 | 保存依据和出处 | 一个来源可用于多份材料；多个来源也可整理为一份材料 |
| 来源定位 | 支持回看和核对 | 与具体来源内容版本关联，不能只留下可能变化的 URL |
| 采集会话 | 管理持续获取的范围和时间 | 可暂停、继续或停止；停止后仍可整理已获取部分 |
| 整理方案 | 复用用户要求 | 任务记录采用的方案版本和本次覆盖要求；改方案不重写旧材料 |
| 草稿 | 承载待确认结果或变更 | 拒绝或重新生成不改变已经保存的材料 |
| 材料及版本 | 保存用户确认结果 | 有稳定身份；改名或移动不改变身份；修改生成新版本 |

这些是目标业务边界，不要求立即建立同名数据库表或独立服务。当前代码仍以会话的一份 `pending_draft` 和 Markdown 文件为中心。

材料间的来源关系应允许：

- 一次会议生成一份纪要和一份待办；两份材料可引用相同发言。
- 多篇网页生成一份对比材料；冲突观点保留各自依据。
- 一个视频拆成多份操作材料；截图与对应步骤共同关联原始时间区间。
- 使用已有材料生成新材料；引用应识别所依据的材料版本，不因原材料后来修改而静默变义。

## 5. 内容、依据与权限边界

### 5.1 来源与正式材料分别管理

来源是核对依据，正式材料是用户确认保留的结果；用户确认表达保存意愿，不构成事实正确性的证明。自动采集、转写和未确认草稿不默认混入已确认材料的检索范围。

整理当前任务时可以读取该任务来源；用户明确要求查找原始来源时，也可以在标明范围的来源检索中查找。两者都必须显示内容身份，不能假装已经经过人审。

获取网页后至少保留所引用的正文片段、定位、获取时间及内容指纹，使网页变更后仍能核对生成时的依据。完整快照、整段录音和完整视频的保留量由对应版本方案确定；引用需要的附件不能被当成普通缓存自动清理。

用户主动删除来源或附件时，提示受影响的引用；允许保留材料并显示依据已不可用，不能承诺仍可精确回看。删除一份材料也不能自动删除其他材料共用的来源。

### 5.2 材料的保存形式

当前文字笔记继续使用 Markdown。多模态材料由正文、必要附件、来源定位和版本信息共同表达；Chroma 等检索索引是派生数据，可由保存内容重建。

材料应有稳定身份，路径用于组织和展示。导出和搬移应保留必要附件与关联信息；具体目录布局、元数据格式和迁移方式在对应版本技术设计中确定。

### 5.3 采集授权与保存确认

用户开始采集时指定范围，系统可以在范围内保存来源片段、截图和恢复检查点。Collector 不拥有正式材料的写入或审批权限。

正式材料的变更经用户确认执行；直接编辑后点击保存也属于用户操作。长结果可以按明确章节或变更项审核；审批粒度在引入该界面的小版本中确定，不能由系统猜测扩大。

重复审批、网络重试或恢复不能重复追加内容。审批前若目标材料已变更，应提示冲突并重新核对，不能覆盖用户较新的编辑。

### 5.4 定制的范围

基础整理方案包括输出结构、详细程度、语言、图片要求和来源呈现方式，可创建、修改并重复使用。任务内补充要求覆盖方案默认值，但不能改变采集范围与写入权限。

任务记录使用时的方案快照或版本，避免用户修改方案后无法解释旧结果。通用 Agent 编辑器、任意脚本、工具市场及多 Agent 编排不属于基础整理方案的交付要求。

## 6. 状态与异常处理

记录任务、材料保存和检索索引分开表达状态。下面是目标业务行为，具体状态字段由实现计划定义。

| 对象 | 主要状态 | 异常处理 |
|------|----------|----------|
| 记录任务 | 已提交、获取中、整理中、待确认、已完成；也可失败或取消 | 记录失败阶段与已有产物；从可恢复阶段重试，不默认重做已成功的采集 |
| 持续采集 | 采集中、已暂停、已停止或中断 | 停止后不产生新数据；已有片段仍可选择整理或删除 |
| 草稿 | 待确认、需修改、已拒绝、已保存 | 退回形成修订；保存失败保留草稿；已保存内容不因拒绝新草稿而消失 |
| 材料 | 已保存的具体版本、已删除 | 删除和版本变化传播到检索；多个引用指向同一版本时保持一致 |
| 索引 | 待更新、已就绪、更新失败 | 保存成功而索引失败时，只重试索引，并明确说明暂不能完整检索 |

含多个草稿的任务，只有所有交付项都已保存、被用户拒绝或明确取消后才结束；一个草稿保存不能掩盖其他未处理项。取消任务不自动撤销已经确认保存的材料。

未来关闭聊天页面不取消已接受的后台任务；删除聊天会话不级联删除独立记录任务和材料。当前待审草稿仍属于会话，删除会话会丢弃它；这一差异应在任务独立化时通过迁移和测试处理。

## 7. 业务能力到技术边界

| 业务能力 | 目标技术责任 | 当前基础与引入时机 |
|----------|--------------|--------------------|
| 表达记录目标 | 对话或其他入口解析范围与要求 | 复用 ChatAgent；V2 逐步输出明确任务输入 |
| 获取不同来源 | Adapter 输出带定位的内容；持续采集输出事件 | V2 网页先引入；V3 再增加文件、音视频和区域采集 |
| 按方案整理 | Composer 根据来源与方案生成草稿，执行确定性校验 | 从当前 ChatAgent 分离；V2.2 与 V2.6 完成基础方案 |
| 任务恢复 | 持久化任务阶段、错误、幂等信息和产物引用 | V2.5；先使用简单后台执行，独立队列按实际需求引入 |
| 确认与保存 | 草稿修订、冲突检查、正式材料版本与附件管理 | 复用现有审批和文件操作；V2 起逐步引入稳定身份和版本 |
| 查找与回看 | 返回内容、版本、来源定位及可用性 | 复用 RAG；V2 文字引用，V3 图片和时间定位 |
| 评价效果 | 场景样本、指标与实际修正成本 | 延续现有离线评测；新来源增加获取和定位评测 |

保持模块化单体作为核心部署。桌面采集器因系统权限和生命周期独立，可以在 V3 单独运行；无需因此把每个业务能力都拆成服务。

对话摘要和短期上下文用于继续交互，不代替来源档案或正式材料。工具全文退出模型上下文，不意味着作为来源保留的内容也必须被删除。

## 8. 版本定义与验收原则

版本路线中的 V1/V2/V3 是产品能力阶段，不等同于包版本号或发布 Tag。各小版本详细要求统一在 [versions.md](../roadmap/versions.md) 维护，本文只定义分阶段原则。

- **V1：文本闭环。** 聊天输入能形成用户确认的笔记，并在后续对话中检索；拒绝、修改、删除与恢复行为有验收证据。
- **V2：可信文本材料。** 在文本闭环上增加质量基线、来源追溯、指定网页、恢复能力和基础整理方案。
- **V3：多模态记录与复用。** 按场景交付文件、图片、会议录音、视频与区域采集；每种来源都能生成可核对的材料并检索回看。

OCR、转写或抓取模块单独可用，只能说明一个技术任务完成。声明某场景小版本完成时，需要演示“指定输入 → 整理 → 确认保存 → 新任务中检索与回看”。

每个小版本在编码前确定用户场景、支持范围、交付结果、失败行为、排除项、质量门槛与验收证据。版本可处于“规划、实现中、待验收、已验收”；出现部分实现时写出具体能力，不用百分比代替证据。

## 9. 如何评价业务效果

| 维度 | 核对的问题 | 验收证据 |
|------|------------|----------|
| 获取 | 所选范围有没有漏内容、顺序错误或串入其他范围？ | 带人工标注的获取样本 |
| 整理 | 是否符合用户意图，是否捏造、遗漏或错误补充？ | 按整理类型划分的评测报告 |
| 定位 | 文字、图片和时间是否对应，引用能否回到依据？ | 引用逐条检查及回看演示 |
| 保存与恢复 | 拒绝、重试、中断是否造成丢失或重复修改？ | 自动化测试与故障恢复记录 |
| 复用 | 新问题能否找回有效材料，是否返回旧版本或无依据答案？ | RAG 查询集和跨任务场景 |
| 用户成本 | 用户核对和修正花了多久，是否比手工整理省事？ | 场景试用记录，先建立基线再定目标 |

学习笔记、忠实摘录和会议纪要分别评测，不强制用“知识加工增益”评价所有材料。自动评分服务离线比较；运行时确定性校验与用户确认承担各自职责，独立模型 Reviewer 只有证明收益后再加入。

## 10. 演进顺序与待决策边界

1. 完成 V1.4 的现有闭环验收，明确当前生成质量和检索基线。
2. V2 分离来源、整理与确认职责，交付指定网页和可复用整理方案；恢复能力随任务引入，不推迟到全部功能结束后补做。
3. V3 先用固定离线材料做完整场景，再增加实时采集。优先级可以调整，来源定位、人审保存和复用验收不能省略。
4. 每个阶段只实现当前场景需要的对象和字段，保留现有 Markdown 内容并通过迁移维护引用。

| 尚未固定的选择 | 决策时点 | 所需依据 |
|----------------|----------|----------|
| 首个多模态场景优先视频还是会议 | 启动对应 V3 实现计划前 | 用户实际记录频率、代表样本和收益 |
| 全量视频/音频的保留期限和容量 | 开始音视频持久化设计前 | 回看需求、磁盘成本与删除规则 |
| 浏览器扩展或桌面入口的具体形态 | 指定 URL 闭环验收后、入口扩展前 | 手动提供 URL 的实际操作负担 |
| 部分审批的具体粒度 | 长材料审核界面设计前 | 材料长度、一次修改范围及用户核对成本 |
| 更深的 Agent 定制方式 | 基础整理方案投入使用后 | 无法用现有方案表达的实际任务 |

这些选择不阻塞当前文本闭环和上层业务定义，也不能被当作已承诺的近期功能。
