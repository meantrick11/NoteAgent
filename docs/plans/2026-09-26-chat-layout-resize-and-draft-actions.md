# 聊天三栏宽度调节与草稿操作收敛：Qoder 执行计划

> **交给 Qoder 执行：**先阅读 `CLAUDE.md`（若存在）、`AGENTS.md`、`docs/architecture/frontend.md` 和本计划引用的现有代码；遵循仓库约定。完成实现、测试和文档更新后，汇报改动及测试结果。不要擅自提交、推送、合并或发布。

**目标：**减少右侧草稿操作按钮的常驻数量，并允许用户通过拖动栏间分隔线调整聊天视图三个区域的宽度，记住布局设置。三个区域是左侧会话列表、中间聊天页面、右侧笔记/草稿面板。

**设计决定：**保留常驻的“批准”和“拒绝”操作；将覆盖类操作收进“更多操作”，用户选择“追加到笔记”或“新建笔记”后再显示对应表单。两个分隔线分别调节左侧栏宽度和右侧面板宽度；中间聊天区使用剩余空间，因此拖动任一分隔线时它会相应伸缩。持久化左侧和右侧宽度即可表达三栏布局，不要为中间区另存一个相互矛盾的固定宽度。

**依据：**用户确认三个区域均可调；鼠标移到分隔线后左右拖动；调整结果需要记住。草稿仍显示在现有右侧笔记/引用区域，草稿创建、编辑、保存和审批语义保持不变。当前实现参照 [home.html](../../src/noteagent/web/templates/home.html)、[前端架构说明](../architecture/frontend.md) 和 [草稿面板计划](./2026-09-26-chat-draft-in-citation-pane.md)。

浏览器验证（隔离实例：SQLite + 临时 notes 目录，端口 8123，不碰真实库与 `notes/`；当前浏览器窗口仅约 600px 宽）：

- 已实测：常驻按钮、菜单开合与 `aria-expanded`、两种覆盖方式互相替换表单、追加到所选笔记的完整提交、Escape 只收菜单并回焦触发器、`setCiteBusy` 同时禁用常驻按钮/菜单项/表单提交。
- 已实测（调宽）：两条分隔线几何与 ARIA、拖动两个方向与两端 clamp、拖动中临时 class 与 `body.cursor`、`pointercancel` 收尾并保存、真实 `ArrowLeft` / `Shift+ArrowLeft`（10px / 40px）、`Home`/`End` 到边界、只在拖动结束与键盘后写存储、刷新后恢复意图并按当前视口重新收边、缺失/非 JSON/非数字/越界/`localStorage` 内容异常都回退默认、面板隐藏时右分隔线跟随隐藏、Documents 视图无分隔线且不被 Chat 宽度影响、`documentElement` 无横向溢出。
- **未能实测**：窗口宽度只有约 600px，三栏在真实视口下都已被收边到最小值，因此宽窗口下"拖动改变可见宽度"的视觉结果没有实测——拖动数学与状态是**把 `innerWidth` 临时改写为 1400 后**跑通的。极端窄窗口（< 500px）同样未实测，只验证了边界公式。这两项请由项目负责人在宽窗口手动确认。

已知取舍：

1. replace / delete 没有「更多操作」入口。改动前的卡片也不提供 replace/delete 的 override，所以这不是静默移除功能；后端 `override` 仍支持这两种 `write_action`，只是前端不发。
2. 覆盖表单一次只渲染一种，切换方式时另一张表单连同其输入一起丢弃；这与"避免多个表单同时占位"一致，但没有为切走的表单保留输入值。
3. 窗口 resize 只重新收边、不写存储，所以把窗口缩到很窄再放大，宽度会回到用户原来的意图而不是停留在收边后的值。

## 全局约束

- 仅调整 Chat 视图的栏宽与草稿操作呈现，不改变草稿数据、创建、编辑、保存、审批 API、笔记写入或引用定位行为。
- 左栏和右栏各有一个可拖动分隔线；中间聊天区随剩余可用宽度变化。Documents 视图不得出现这些分隔线，也不得被 Chat 布局持久化逻辑改变。
- 右侧草稿面板常驻“批准”和“拒绝”；追加、新建等覆盖方式通过“更多操作”选择，选择后只显示所选方式需要的表单。保留既有支持的操作及其 API 语义。
- 交互需支持鼠标、触摸/触控笔 Pointer Events 和键盘；提供可见焦点、合理的 `role="separator"`、ARIA 标签和值范围。
- 保存布局时只存栏宽，不存草稿、笔记内容、会话内容或文件名。损坏或不可用的 `localStorage` 不应阻断页面使用。
- 保持当前前端技术栈和视觉风格，不引入新的 UI 框架或依赖。

## Task 2：实现三栏拖动调宽与记忆

### 布局和约束

持久化 `sidebarWidth` 与 `notePaneWidth` 两个值。中间聊天区采用 flex 剩余空间布局，不持久化固定宽度。默认值优先沿用当前体验：左栏约 `260px`、右栏约 `400px`；调整前检查现有 CSS、窗口尺寸和 Documents 布局，再确定实际 min/max。建议初始边界为左栏 `200–400px`、右栏 `300–600px`、中间区至少 `440px`，并根据现有布局验证边界不会挤坏窗口。

- [x] 检查 `.app-shell.active`、`.sidebar`、`.main`、`.main-stage`、`.chat-container`、`.cite-pane` 和所有相关媒体查询；确认当前 flex/grid 约束、滚动容器以及 `#viewDocs .sidebar` 的布局隔离。
- [x] 仅在 Chat 主布局中添加两个分隔线：会话列表与主聊天区之间 `conversationResizeHandle`；聊天内容与笔记面板之间 `notePaneResizeHandle`。右侧面板隐藏时隐藏第二个分隔线。
- [x] 分隔线提供约 8px 的命中区域、清晰 hover/focus 状态和 `col-resize` 光标；设置 `role="separator"`、`aria-orientation="vertical"`、可理解的 `aria-label`、`tabindex="0"` 及动态 `aria-valuemin/max/now`。
- [x] 用 Pointer Events 完成拖动，支持 `setPointerCapture`、`pointermove`、`pointerup` 和 `pointercancel`；拖动期间实时更新对应栏宽和 ARIA 值，结束/取消时清理 dragging class、body cursor、`user-select` 等临时状态。
- [x] 每次更新宽度都 clamp 到边界，并结合当前窗口宽度保证中间聊天区仍至少达到最小可读宽度；若窗口本身小于三栏最小宽度之和，按明确的窄屏布局规则降级，不能产生页面级横向溢出。窗口 resize 后重新 clamp 当前值。
- [x] 键盘聚焦分隔线时支持 Left/Right 每次 10px、Shift+Left/Right 每次 40px、Home/End 跳到该栏允许的最小/最大宽度；处理事件时阻止滚动键影响页面，并同步更新 ARIA 值。
- [x] 使用版本化键 `noteagent.chat-layout.v1` 存储 `{ sidebarWidth, notePaneWidth }`。初始化时安全读取并校验类型、有限数值和范围；缺失、损坏、越界或 `localStorage` 不可用时回退到默认宽度，页面仍可正常使用。
- [x] 在拖动结束和键盘调整后保存布局，不要在每个 `pointermove` 事件里写存储。恢复保存值后仍按当前视口重新 clamp。
- [x] 确认 Documents 视图不创建/显示 Chat 分隔线，也不读取或应用 Chat 的栏宽状态。
- [x] 为稳定行为添加模板/集成断言，覆盖两个 separator 的存在、ARIA 属性、存储 key 和 Chat/Documents 隔离所需的结构 hook；若当前测试层无法执行 JavaScript，不要用静态断言冒充拖动或浏览器行为验证。
- [x] 手动浏览器验收时检查 hover 光标、左右拖动、最小/最大边界、中间区最小宽度、取消拖动、刷新后恢复、无效存储回退、键盘调整、窄窗口和 Documents 视图隔离，并如实记录环境及结果。

## 完成标准

- 用户可通过两个分隔线调节左侧会话列表宽度和右侧笔记面板宽度；中间聊天区随剩余空间弹性变化。
- 布局宽度在刷新后恢复，非法/不可用存储安全回退；键盘及指针操作均可用，极窄窗口不发生不可接受的溢出。
- Documents 视图不受 Chat 调宽功能影响。
- 草稿面板默认只常驻批准/拒绝；其他既有覆盖操作可从更多操作进入，并且一次只展示所选操作对应的表单。
- 草稿创建、编辑、保存、引用与审批行为保持原有语义；实现测试结果和人工验收边界均如实记录。
