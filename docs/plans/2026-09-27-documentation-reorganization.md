**需求依据：** 用户于 2026-09-27 明确要求本轮由 Qoder 重新组织文档，暂时不考虑前端设计。此前讨论的页面结构和 Vue 方向在文档整理完成后另行设计，本轮不创建其规格或实施计划。

## 0. 全局约束

- 本轮只修改文档，以及为迁移文档而必需调整的历史画布引用；不修改应用代码、接口、数据库、测试、构建配置或依赖。
- 不创建或补写 Home、Assistant、Library、Records、Settings 的产品设计、路由设计、Vue 技术选型、组件设计、迁移设计或前端实施计划。不将聊天中的讨论写成已经实现的功能。
- 保留当前 Chat / Documents 架构说明，依据当前代码核查；未来前端改动由后续独立任务处理。
- 不改变产品范围、V1/V2/V3 退出标准、审批边界和评测门槛。发现有效需求与实现不同，记录缺口，不能通过改需求或改代码让两者表面一致。
- 不读取或输出密钥，不访问私人笔记正文；不修改 `notes/`、原始评测数据、运行时配置及运行产物。评测核查优先使用已归档的配置和汇总。
- 不删除历史设计；归档时保留正文含义，并说明哪些假设失效。不把历史全文改写成新设计。
- 不以创建日期、文件名或勾选框独立判断完成状态。实现、测试存在与执行通过是不同证据；不可把代码存在当成已验收。
- 本轮不运行真实 LLM、向量模型下载或数据库迁移，不执行模型评测。文档变更通常只需静态验证；测试结果引用已有证据，并标明日期和提交。
- 不执行 `git reset`、`git clean`、批量暂存、提交或推送。所有已有用户改动保留。
- 文档可能混有 UTF-8、GB18030 及异常换行；读取前检查编码。禁止用替换字符吞掉解码错误，禁止全仓库自动转码或格式化。只对本轮实际修订文档做必要规范化，并检查中文没有损坏。

## 1. 目标目录职责

| 位置 | 唯一主要职责 | 本轮处理原则 |
|---|---|---|
| `docs/README.md` | 文档入口、阅读路径、维护规则 | 重写导航，明确现行/未来/历史边界 |
| `docs/product/` | 有效产品目标、业务流程与边界 | 核查现有文档，不新增前端产品设计 |
| `CONTEXT.md` | 业务术语 | 只在确有冲突且依据明确时修订，不重复业务全貌 |
| `docs/roadmap/` | 阶段范围、退出标准、验收状态 | 排除代码讲解的权威性，保持阶段要求 |
| `docs/architecture/` | 当前代码已经实现的结构与行为 | 依据代码核查，隔离旧设计 |
| `docs/design/` | 有效的未来技术设计 | 本轮只明确目录职责，不创造新方案 |
| `docs/plans/` | 实施任务、完成情况、验证入口 | 保留已完成计划；废弃设想移出 |
| `docs/decisions/` | 重要选择的原因与替代关系 | 不追造缺乏证据的历史决策，不强行为每个改动写 ADR |
| `docs/evaluations/` | 评测准则、运行报告、验收证据 | 保留历史运行身份，错误通过勘误修正 |
| `docs/tutorials/` | 使用、开发与代码阅读教程 | 保留现有层级；已过时步骤核查后修订 |
| `docs/references/` | 外部摘录和个人思考 | 明确非开发契约，用户文件不覆盖 |
| `docs/archive/` | 被替代、废弃的设计与附属材料 | 新增索引、失效原因和替代链接 |

已完成计划不自动归档。历史评测报告不因实现变化而失效。无新内容的目录无需为了显得完整而增加正文。
